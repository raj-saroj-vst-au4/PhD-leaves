# 2026-09-23 security audit remediation — production runbook

For whoever deploys to chanakya (`r4id@10.127.1.1`, portal at `/var/www/html/phdtimeoff`).
Do the steps in order. Each step says how to check it worked. **Do not deploy this
file** to the web root (nginx would serve it); the scripts next to it are CLI-only.

Shorthand below: `P=/var/www/html/phdtimeoff`, `U=https://www.som.iitb.ac.in/phdtimeoff`.

### 0b. Rotate the `timeoff_user` database password

The old password must be treated as public. This needs a MariaDB account that can
`ALTER USER` (r4id's `timeoff_user` cannot change itself on every setup).

1. `openssl rand -base64 24` → new password.
2. As a MariaDB admin: `ALTER USER 'timeoff_user'@'localhost' IDENTIFIED BY '<new>';`
3. Immediately edit `DB_PASS` in `$P/config/database.php` (the only consumer on
   chanakya; the attendance backend uses its own `attendance_app` account —
   confirm with `grep DB_USER /home/r4id/phd-attendance/.env`).
4. Check: `curl -s -o /dev/null -w '%{http_code}\n' "$U/login.php"` → 200, and sign in.
5. If you can read nginx access logs, look for earlier hits on `install.php` to see
   whether anyone else fetched the form: `grep -h 'install.php' /var/log/nginx/access.log*`.

## 4. Deploy the code

Ship the commit, not the working tree (`git archive HEAD -- <files> | ssh … 'tar x -C /var/www/html/phdtimeoff'`).

- **This deploy must include `config/constants.php`.** The new code reads constants
  it defines (`APP_TIMEZONE`, `FORCE_HTTPS`, `TLS_TERMINATING_PROXIES`,
  `PRIVATE_DIR`, `MEDICAL_DOCS_DIR`, `DEAN_AP_DOCS_DIR`, `LOG_DIR`). It is now
  committed with production's values (`SITE_DOMAIN` = `https://www.som.iitb.ac.in`)
  and safe to ship; a host that differs (dev) puts its own values in the gitignored
  `config/site.php` (see `config/site-example.php`). Production needs no `site.php`.
  Diff production's current `constants.php` against the old commit first and carry
  over anything else production had changed.
- Still never ship `config/database.php`, `config/mail.php`, `config/attendance.php`.
- Include the new files: `api/files/download.php`,
  `captcha.php`, `includes/captcha.php`, `includes/rate_limit.php`,
  `public/vendor/inter/*`, `database/create_admin.php`, `database/fixes/*.php`.
- Remove on production what the commit deletes:

  ```sh
  rm -f $P/install.php $P/includes/email_usage_example.php \
        $P/cron/*.php.bak.* $P/public/vendor/tailwind/tailwind.min.css.bak.*
  ```
- **Leave `.private/` out of the archive** (or re-run step 3's `chmod` afterwards):
  extracting a directory entry resets its mode to 0755 and www-data can then no longer
  save medical certificates ("Failed to save uploaded file"). `.private/.htaccess` is
  only for Apache on dev and is not needed on production.
- Then `php -l` every shipped PHP file under PHP 8.3.
- The session cookie is renamed in this release (`PHDTIMEOFF_SID`, path `/phdtimeoff/`),
  so **everyone is signed out once** when it goes live. Tell users beforehand if that matters.
- The office attendance code screen (`admin/attendance_display.php`) now runs on its
  own 16-hour display token instead of keeping an admin session alive: an admin or
  HOD opens it each working day; after their session times out it keeps running, and
  reloading it means signing in again.

## 5. Move the existing private files

```sh
cd $P
ls -ld public/uploads/medical_documents logs          # r4id needs write on these to move files out
mv public/uploads/medical_documents/*.pdf .private/medical_documents/ 2>/dev/null
mv logs/*.log logs/*.csv .private/logs/ 2>/dev/null
ls public/uploads/medical_documents logs              # only .gitkeep / .htaccess should remain
```

Stored references (`uploads/medical_documents/<name>.pdf`) keep working: the download
endpoint resolves them by basename inside `.private/medical_documents/`. If `mv`
says *Permission denied* (directory owned by www-data without group/other write),
someone with root must move them — do not leave them in place.

Old Dean AP uploads: the previous admin page saved them straight into
`public/uploads/` with the uploader's own file extension (then crashed). Anything
there other than `.gitkeep`, `.htaccess` and `medical_documents/` is such a leftover
and is still web-served — and a `.php` one would execute:

```sh
ls -la public/uploads/          # review, then remove the leftovers
```

Orphans: list certificate files no leave references and delete them once reviewed:

```sh
php -r 'require "config/constants.php"; require "config/database.php";
  $ref = array_map("basename", getDBConnection()->query("SELECT supporting_document FROM leave_applications WHERE supporting_document IS NOT NULL")->fetchAll(PDO::FETCH_COLUMN));
  foreach (glob(MEDICAL_DOCS_DIR."*.pdf") as $f) if (!in_array(basename($f), $ref, true)) echo $f, "\n";'
```

## 8. Data fixes (all dry-run by default)

### 8a. Missed July balance reset


most recent reset date.

### 8c. Leaves waiting at the TA stage where the guide is the TA

```sh

php database/fixes/2026_09_23_settle_guide_ta_pending.php --apply --admin-id=<admin users.id>
```

expected to be that shape: they sit in the TA queue of the faculty member who is both
guide and TA, and need that person's one approval. Chase them — or, if they cannot
act, change the students' TA in Admin → Users (removing the TA now sends such an
application back to the guide stage; a TA who is someone else simply receives it).

The report at the end lists the rest of the long-stale queue (leaves 18 and 30 wait
on TA coordinator user 114) — those need a person too.
